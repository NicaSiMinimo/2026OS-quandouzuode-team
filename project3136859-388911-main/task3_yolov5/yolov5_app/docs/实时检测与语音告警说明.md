# 实时检测与语音告警说明

## 使用方式

进入“实时摄像头”后，顶部可切换“工作 / 安检 / 公共”三种场景。语音按钮可随时静音；工作场景还可把禁区切换为画面左侧、右侧或关闭。

规则只使用实时预览帧，不录像、不保存摄像头画面。检测结果来自当前 YOLOv5s COCO 80 类模型，规则层通过连续帧确认、空间关联、持续时间和播报冷却降低瞬时误报。

## 工作场景

| 功能 | 判断方式 | 默认时序 |
| --- | --- | --- |
| 人员到岗 | 连续检测到 `person` | 1.2 秒确认 |
| 人员离岗 | 工作区域持续未检测到人员 | 10 秒确认 |
| 人数异常 | 同时检测到 2 人及以上，默认人数上限为 1 | 1.8 秒确认，20 秒冷却 |
| 禁区闯入 | 人员框中心进入画面左侧或右侧 28% 禁区 | 1 秒确认，15 秒冷却 |
| 疑似使用手机 | `cell phone` 位于人员框上半身附近 | 1.2 秒确认，20 秒冷却 |
| 关键设备缺失 | 启动后自动学习显示器、笔记本、键盘、鼠标；学到的设备持续消失才报警 | 12 秒学习；消失 8 秒后确认；30 秒冷却 |

“疑似使用手机”只是手机与人员上半身的空间关联判断，不能据此断言“正在打电话”。

设备基线学习期间应保持摄像头和关键设备位置稳定。某类设备在学习阶段至少稳定出现 3 帧，才会成为本次监控的预期设备；切换离开工作场景再切回会重新学习。

## 安检场景

| 规则 | 当前模型可识别的类别 | 处理方式 |
| --- | --- | --- |
| 疑似危险物品 | `knife`、`scissors` | 0.7 秒确认，要求人工复核 |
| 食品饮品 | 瓶、杯、餐具、碗及 COCO 中的常见食品 | 1 秒确认，要求人工复核 |
| 包裹行李 | `backpack`、`handbag`、`suitcase` | 1 秒确认，要求人工复核 |

普通 COCO 模型不是专业 X 光安检模型，遮挡、透明容器、小刀具和外观相似物体可能漏检或误检，因此界面统一使用“疑似 / 复核”措辞。

## 公共环境

| 功能 | 判断方式 |
| --- | --- |
| 疑似遗留物 | 对背包、手提包、行李箱做相邻帧位置跟踪；基本静止至少 15 秒，同时附近持续无人至少 10 秒 |
| 人员聚集 | 同时检测到 4 人及以上并持续 2.5 秒 |
| 动物进入 | 检测到鸟、猫或狗并持续 1.2 秒 |

遗留物跟踪允许短暂漏检 2.5 秒；物体明显移动或人员重新靠近后，静置计时会重置。该方案是轻量级规则跟踪，不包含跨镜头 ReID。

## 语音资源

12 条提示音位于 `entry/src/main/resources/rawfile`，由 `D:\WORK\MyScripts\tts.py` 使用 `zh-CN-XiaoxiaoNeural` 音色提前生成。运行应用时只播放已打包的本地 MP3，不调用 TTS 服务，也不需要联网。

修改脚本中的提示语后执行：

```powershell
python -u D:\WORK\MyScripts\tts.py
```

脚本会依次重新生成全部提示音。每条语音先写入临时文件，生成完整后才覆盖应用中的同名 MP3；连接失败会自动重试，不会破坏原有可用资源。

## 当前模型边界

当前模型没有“吸烟 / 香烟 / 安全帽 / 未戴安全帽”类别，因此本版本不会用不相关类别拼凑这些结论。要实现这些功能，应替换或增加针对工作场景训练的专用模型，再在 `SceneRuleEngine.ets` 中接入其类别。

COCO 的 `tv` 类在本项目中显示为“显示器”；对小尺寸键盘、鼠标和手机的召回率受摄像头距离、光线及 640×640 模型输入影响。现场部署前应按固定机位采集样本，分别评估漏检率和误报率，再调整置信度与确认时间。

## 主要代码

- `entry/src/main/ets/pages/LiveCamera.ets`：实时推理、界面、检测框、场景切换和语音队列。
- `entry/src/main/ets/rules/SceneRuleEngine.ets`：三种场景的时序、空间和状态规则。
- `D:\WORK\MyScripts\tts.py`：中文提示音素材生成器，输出直接进入应用 `rawfile`。
